# 第一章：什么是 Skill

## 核心定义

**Skill = 可复用的程序记忆**

它是 Hermes Agent 学习和积累经验的方式。当 Hermes 解决了一个复杂问题、发现了一个工作流程、或者被用户纠正了做法，它可以将这些知识保存为一个 Skill 文件，供未来的会话使用。

## 为什么需要 Skill

### 问题场景

```
会话 1：你花了 30 分钟配置 frpc 穿透
会话 2：你又忘了怎么配，又要花 30 分钟
会话 3：同样的问题再来一遍...
```

### 解决方案

```
会话 1：配置 frpc 穿透 → 保存为 Skill
会话 2：自动加载 Skill → 5 分钟搞定
会话 3：直接使用 → 5 分钟搞定
```

## Skill vs 其他概念

### Skill vs Memory

| 维度 | Skill | Memory |
|------|-------|--------|
| 用途 | 存储"怎么做" | 存储"是什么" |
| 格式 | YAML + Markdown | 纯文本 |
| 位置 | `~/.hermes/skills/` | `~/.hermes/memory.md` |
| 示例 | "如何创建 FastAPI 项目" | "用户喜欢用 dev 分支" |

### Skill vs 脚本

| 维度 | Skill | 脚本 |
|------|-------|------|
| 执行者 | Hermes（AI） | 计算机 |
| 灵活性 | 高（AI 可以适应变化） | 低（严格按代码执行） |
| 适用场景 | 复杂、需要判断的任务 | 固定、重复的任务 |

### Skill vs 文档

| 维度 | Skill | 文档 |
|------|-------|------|
| 目标受众 | AI | 人类 |
| 格式 | 结构化（触发条件、步骤、验证） | 自由格式 |
| 执行方式 | 自动加载执行 | 人工阅读参考 |

## Skill 的价值

### 对用户

1. **节省时间** — 不用重复解释同样的事情
2. **知识积累** — 经验不会丢失
3. **一致性** — 每次都按最佳实践执行
4. **可分享** — 团队可以共享 skill

### 对 Hermes

1. **学习能力** — 从经验中学习
2. **效率提升** — 不用每次重新推理
3. **质量保证** — 按照验证过的流程执行
4. **减少幻觉** — 基于事实而非猜测

## 实际案例

### 案例 1：项目创建

**没有 Skill 时：**
```
用户：创建一个 Python 项目
Hermes：好的，我来创建...
[创建目录]
[写 README]
[初始化 git]
[创建 conda 环境]
[安装依赖]
... 20 分钟后 ...
```

**有 Skill 时：**
```
用户：创建一个 Python 项目
Hermes：[加载 python-project-scaffold skill]
[按照标准化流程执行]
... 5 分钟后 ...
```

### 案例 2：问题排查

**没有 Skill 时：**
```
用户：后端启动失败了
Hermes：让我看看...
[检查端口]
[查看日志]
[搜索错误]
```

**有 Skill 时：**
```

```

## 面试常见问题

### Q1：Skill 和传统的 if-else 规则有什么区别？

**答：**
- Skill 是给 AI 的指导，不是硬编码规则
- AI 可以根据上下文灵活调整
- Skill 包含"触发条件"和"验证清单"，比 if-else 更完整
- Skill 可以被 AI 自动发现和加载

### Q2：Skill 的局限性是什么？

**答：**
- 依赖 AI 的理解能力，可能误判
- 需要人工维护，过时的 skill 会误导
- 复杂逻辑不适合用 skill（用脚本更好）
- 不适合实时性要求极高的场景

### Q3：什么时候应该用 Skill，什么时候用脚本？

**答：**
- **用 Skill：** 需要判断、上下文理解、灵活应变的任务
- **用脚本：** 固定流程、无需判断、需要精确控制的任务
- **组合使用：** Skill 调用脚本完成具体操作
